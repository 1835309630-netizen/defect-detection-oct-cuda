# 缺陷检测

双击 `缺陷检测程序/缺陷检测生产端V2.exe` 使用检测程序；双击同目录 `模板生成器.exe` 生成模板。两个EXE共用运行库，请保留整个程序目录。

## 文件结构

```text
源码/
├─ 缺陷检测/                       Windows界面和相机
│  ├─ MainForm.cs                  程序入口、生产界面、检测操作
│  ├─ CameraController.cs          相机控制及帧数据类型
│  ├─ ImagePipeline.cs             TIFF保存、算法进程及报告类型
│  ├─ TemplateForm.cs              模板生成窗口
│  ├─ 相机显示.cs                  大恒官方显示类及辅助类型
│  ├─ 缺陷检测生产端.csproj         唯一项目/构建配置
│  └─ app.manifest                 Windows运行声明
└─ 算法引擎/
   ├─ 检测引擎.py                  预处理、保存、命令行JSON接口
   ├─ defect_algorithm.py          检测、轮廓匹配、多图模板生成
   ├─ requirements.txt             构建机Python依赖
   └─ 模板/                        初始type_a.png、type_b.png
缺陷检测程序/                      最新完整运行包
原版程序备份/                      优化前原程序，含原源码ZIP
README.md                          唯一说明
```

按“界面/设备”和“算法”分成两部分。小数据类型已并入使用它们的模块，入口并入主窗口文件，模板生成算法并入算法模块，大恒显示三文件合并为一个文件但保持原有类和官方API行为。没有独立构建脚本、额外props配置、重复说明或专用测试目录。csproj中已统一SDK根路径及中间产物位置。

## 采集和保存

连接相机后设置曝光并回读。左侧“采集/标定保存目录”供普通采集、背景、平场共用；右侧“检测结果保存目录”供检测使用。

每次触发检测后，界面显示的带红框结果帧按采集时刻保存为：

```text
所选检测结果目录/
├─ 2026-09-07/
│  ├─ Type A/
│  │  └─ 20260907_143052_123456_Type A.tif
│  └─ 003/
│     └─ 20260907_143058_234567_003.tif
└─ 其他/原始与校正/2026-09-07/143052_123_F帧号/
   ├─ 01_原始帧.tif
   └─ 02_校正帧.tif                 仅启用背景/平场时产生
```

结果目录按每日、零件类型两层分类，不再每次建一个结果文件夹。文件名由完整时间戳和类型组成，同名时自动追加序号避免覆盖。日期和时间来自采集时刻，跨午夜处理不会分到错误日期。无缺陷时也保存结果帧，只是不画红框。原始帧和校正帧仍保留在“其他”，用于追溯。

原始Mono10用16位无压缩TIFF承载0～1023，不改变原始值。校正结果用float32运算并保存32位浮点TIFF；结果帧是显示图，不能代替科学原始数据。本轮未改变算法阈值和灰度域。

## 模板

打开“模板生成器.exe”，选择同一零件的若干不同图片，建议3～9张，点击生成并导出PNG。复制到 `缺陷检测程序/算法引擎/模板/`，按 `001.png、002.png、003.png…` 命名，下一次检测自动参与比较，无需配置或重启。

输入需同分辨率、同倍率、同一成像面，零件完整入镜，材料较亮、背景较暗；可平移和面内旋转。程序分割轮廓、对齐、多数投票，导出一张二值轮廓图，不修改输入。生成对齐IoU低于0.85、尺寸不一或轮廓出框会报错；不支持透视或倍率变化。不要把普通照片直接放入模板目录。

模板只影响零件分类和角度，不参与暗缺陷灰度差分；所有类型仍共用当前缺陷规则。模板目录为空时继续检测并显示“未分类”；目录缺失或模板损坏会报错。分类保持取最高IoU的原有行为，未设最低分拒识，不属于任何已知类型的零件也可能被分到最近的一类。

文件名就是类型名；原type_a/type_b兼容显示Type A/Type B。现场新增模板只在发布目录生效，升级时保留，不要用源码初始模板覆盖现场模板。
