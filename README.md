# 零件缺陷检测系统 + OCT B-scan 重建 CUDA 加速

课程项目代码仓库，包含两项工作：

1. **零件缺陷检测系统** —— C# 生产端（相机采集 + 界面）+ Python 算法引擎（预处理、缺陷判定、模板分类）；
2. **OCT B-scan 重建的 CUDA 加速** —— 以 Python / MATLAB 为基准实现，逐步改写成 CUDA 版本，并做逐像素一致性验收与性能优化，共三个任务（单帧、512 帧、1000×1000）。

> 本仓库只收录**源码与文档**。原始数据（`.dat` / `.mat`）、标定参数（`.bin`）、编译产物（`.exe` / `.dll`）和第三方软件没有上传，原因见文末「仓库约定」。

## 一、零件缺陷检测系统

### 组成

- **生产端（C#）**：连接大恒工业相机，设置/回读曝光，采集图像，调用算法进程，显示带红框的结果帧，按日期和零件类型归档保存。算法以子进程方式调用，通过标准输出交换一条 JSON，界面与算法解耦。
- **算法引擎（Python）**：`检测引擎.py` 负责单帧预处理与命令行入口，`defect_algorithm.py` 负责缺陷判定、轮廓匹配与多图模板生成。用 PyInstaller 打包成 `检测引擎.exe` 供生产端调用。

### 处理流程

1. 采集原始帧（Mono10，16 位无压缩 TIFF 承载 0～1023 原始值）；
2. 可选背景扣除 / 平场校正（float32 运算，不使用 uint8 中间结果）；
3. 缺陷判定：暗缺陷灰度差分规则；
4. 模板分类：分割零件轮廓 → 对齐 → 与模板目录中的多张模板做 IoU 匹配 → 取最高分类型；
5. 输出带红框的结果帧，并保留原始帧与校正帧用于追溯。

### 设计要点

- **原始数据与显示图分离**：结果帧只用于显示，科学原始数据单独保存为 16 位 TIFF / 32 位浮点 TIFF，不互相替代。
- **模板只影响分类**：模板决定零件类型与角度，不参与暗缺陷灰度差分，所有类型共用同一套缺陷规则。
- **模板安全边界**：对齐 IoU 低于 0.85、尺寸不一致、轮廓出框都会报错，不做静默降级；模板目录缺失或损坏同样报错。
- **归档规则**：结果按「日期 / 零件类型」两层分类，文件名由完整时间戳构成，跨午夜不会分到错误日期。

详细使用说明见 `新缺陷检测/缺陷检测程序/使用说明.md`。

## 二、OCT B-scan 重建的 CUDA 加速

三个任务共用同一个思路：**先按老师的权威实现跑出标杆，再写 CUDA 版，最后逐像素对比验收**。

| 任务 | 数据规模 | 标杆（正确性基准） | CUDA 版做法 | 验收结果 |
| --- | --- | --- | --- | --- |
| 单帧 `B_Scan` | 1 帧，2048×256 int16 | Python `getBscan_image.py` | 4 个核函数 + cuFFT | 与 Python 基准逐字节一致 |
| 512 帧 `512任务` | 512 帧，2048×256 | MATLAB `getOCTimage4_1_opt_wykgpu_cpu.m` | cuFFT | 512 张 BMP，约 1～2 分钟 |
| 1000×1000 `1000x1000任务` | 11 帧，825×1000 | MATLAB 原脚本 | 自研 radix-2 FFT，2 个融合核 | 最大差值 1（62 / 9,900,000 像素 = 0.0006%） |

### 性能结果（1000×1000 任务）

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 真实墙钟 | 355 ms | 161 ms（**2.23×**） |
| 帧循环 | 128 ms | 50 ms（**2.6×**） |
| 输出一致性 | — | 12 张输出逐字节完全相同 |

### 主要优化手段

1. **去掉 cuFFT，改用自带 radix-2 FFT**：本机 cuFFT 建一次 4096 点 plan 约 50 ms，比 11 帧的真实计算还贵；改后 exe 不再依赖 `cufft64_11.dll`。
2. **核函数合并**：7 个核函数合并为 2 个（rowMean + 一个「建输入 → 补零 → FFT → 取模 → log10 → 量化 → 累加」的融合核），中间数组全部取消。
3. **CPU 预计算**：只依赖标定和下标的量（插值括号、色散相位 cos/sin、bit-reversal 表、旋转因子）在主机端算一次，消除每个元素重算三角函数、每列重复 1000 次的二分查找。
4. **减少系统调用**：BMP 从「256 次调色板写 + 每行一次 fwrite」（每文件约 1081 次调用）改为内存拼好后一次写出，单这一项省下约 60 ms。
5. **减少显存回传**：平均图累加缓冲留在显存，只在最后回传一次。
6. **软件流水**：写 BMP 与下一帧的核函数重叠执行。

### 原版性能剖析（单帧任务，作为优化依据）

原版 GPU 计时段约 95～100 ms，其中：

- 约 52.7 ms：第一次核函数启动，exe 里只有 `sm_52`，驱动必须现场 PTX JIT；
- 约 45.6 ms：`cufftPlanMany` 建 plan；
- 约 1.4 ms：真正干活的 4 个核函数 + FFT。

也就是说原版 98% 的时间花在启动开销上，这直接决定了后续「去 cuFFT、合并核函数」的优化方向。

## 环境

- **生产端**：Visual Studio + .NET (WPF)，大恒相机 SDK（GxIAPI）
- **算法引擎**：Python 3.14，`numpy` / `opencv-python-headless` / `Pillow`，打包用 `PyInstaller`（见 `requirements.txt`）
- **CUDA 部分**：Visual Studio + CUDA Toolkit 12.8，`nvcc` 编译；对比工具需要 Python + `numpy` + `Pillow`

## 如何运行

CUDA 三个任务都需要课程提供的原始数据（`.dat` / `.mat`）和标定参数（`.bin`），这些文件不在仓库中，需按 `OCT_Bscan_Projects/README.txt` 放回对应位置：

- 512 帧任务：`e3.dat` 放在 `512任务/` 下（cuda 目录的上一级），标定用 `export_calib_bins.m` 从 `.mat` 导出；
- 1000×1000 任务：11 个 `.bin` 放入 `cuda/data/`，对比工具运行 `python compare_1000.py`；
- 编译：进入对应 `cuda/` 目录双击 `build.bat`，运行双击 `run.bat`。
