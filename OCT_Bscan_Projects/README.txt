============================================================
 OCT_Bscan_Projects —— OCT B-scan 重建 CUDA 加速项目合集
============================================================

本文件夹包含两个 OCT 图像重建项目（老师布置的 CUDA 加速任务）：
  项目一：512 帧重建（e3.dat 原始数据，512 张 B-scan 图像）
  项目二：1000×1000 渐进重建（11 帧数据，825×1000 图像）

每个项目内部结构一致，都是三层：
  [老师原始文件]  →  标杆（MATLAB 输出）  →  加速版（CUDA 输出）

============================================================
【项目一】512任务\ —— 512 帧 OCT 重建
============================================================
512任务\e3.dat
    老师提供的原始数据文件（512MB，512 帧 × 2048×256 的 int16 数据）。
    【重要】CUDA 程序用相对路径读取它，必须放在 cuda 文件夹的上一级，
    即本位置，不要移动。

512任务\e3_imfirst.mat
    老师提供的标定文件（MAmean、xi、CArray 等重建参数）。

512任务\getOCTimage4_1_opt_wykgpu_cpu.m
    老师提供的 MATLAB 原始重建脚本（标杆算法，唯一权威版本）。

512任务\matlab_benchmark\
    MATLAB 标杆输出：用老师原脚本跑出的 512 张 BMP 图像，
    是 CUDA 版要逐像素对照的"标准答案"。

512任务\cuda\
    CUDA 加速版（核心交付物）：
      bscan_cuda512.cu    CUDA 源码（C++ + CUDA）
      bscan_cuda512.exe   编译好的可执行程序
      build.bat           一键编译脚本（需 VS + CUDA 环境）
      run.bat             一键运行脚本（双击即可跑，需 exe 已编译）
      MAmean.bin / xi.bin / CArray_re.bin / CArray_im.bin
                          标定参数二进制（从 .mat 导出，供 CUDA 读取）
      cufft64_11.dll      cuFFT 运行时库（程序运行必需，勿删）
      image_e3\           输出：512 张重建 BMP（1.bmp ~ 512.bmp）
      compare_bmp.cpp / compare_bmp.exe
                          图像对比工具（逐像素比较两张 BMP）
      export_calib_bins.m MATLAB 小脚本：把 .mat 标定导出为 bin

运行方法：
  1) 打开 512任务\cuda\ 文件夹
  2) 双击 run.bat（或用命令行运行 bscan_cuda512.exe）
  3) 输出在 cuda\image_e3\，耗时约 1~2 分钟

============================================================
【项目二】1000任务\ —— 1000×1000 渐进重建（11 帧）
============================================================
1000任务\1000×1000(1).zip
    老师提供的原始数据压缩包（含 11 个 .bin 原始数据 + cal_filea.mat
    标定 + getOCTimage4.m 原脚本）。原件，不要删除。

1000任务\matlab_benchmark\
    MATLAB 标杆输出：
      getOCTimage4_bench.m  标杆脚本副本（仅禁用了不影响数值的
                            frq1/parpool/hann，输出与老师原版一致）
      cal_filea.mat         标定文件
      20260720_*.bin        11 个原始数据副本（供 MATLAB 读取）
      OCT_Results\          输出：12 张 BMP（11 帧 + 平均图）
      matlab_run.log        MATLAB 运行日志（含总耗时记录）

1000任务\cuda\
    CUDA 加速版（核心交付物）：
      bscan_cuda1000.cu     CUDA 源码
      bscan_cuda1000.exe    编译好的可执行程序
      build.bat             一键编译脚本
      run.bat               一键运行脚本
      MAmean.bin / xi.bin / CArray_re.bin / CArray_im.bin
                           标定参数二进制
      data\                 11 个原始数据副本（程序从这里读）
      image_1000\           输出：12 张 BMP（11 帧 + 平均图）

1000任务\compare_1000.py
    一键对比工具：读 MATLAB 标杆与 CUDA 输出，逐像素做差，
    输出最大差值、差异像素数统计。
    运行：python compare_1000.py（需已安装 numpy、PIL）

1000任务\comparison_1000.bmp
    对比结果图：上=MATLAB标杆，中=差值放大100倍，下=CUDA输出。
    结论：最大差值 1（62/9,900,000 像素，0.0006%），满足验收标准。

运行方法：
  1) 打开 1000任务\cuda\ 文件夹
  2) 双击 run.bat
  3) 输出在 cuda\image_1000\，约 0.16 秒
     （内部计时：帧循环约 50 ms；另有约 90 ms 是驱动建 CUDA 上下文，躲不掉）

============================================================
【本次优化记录】1000任务（2026-10-10）
============================================================
结果：真实墙钟 355 ms -> 161 ms（2.23x）；帧循环 128 ms -> 50 ms（2.6x）。
      12 张输出与优化前逐字节完全相同，对 MATLAB 标杆仍是 max diff = 1
      （62 / 9,900,000 像素，0.0006%），满足验收标准。

改了什么：
  1) 去掉 cuFFT，改用自带的 radix-2 FFT（共享内存内一次算完）。
     本机 cuFFT 建一次 4096 点 plan 要 ~50 ms，比 11 帧的真实计算还贵。
     附带好处：exe 不再依赖 cufft64_11.dll，换机器只要驱动即可运行。
  2) 7 个核函数合并为 2 个（rowMean + 一个融合核：建输入->补零->FFT->
     取模->log10->量化->累加），中间数组全部取消。
  3) 只依赖标定/下标的量在 CPU 上预计算一次：插值括号 (srcL,srcR,den,q)、
     色散相位 cos/sin、bit-reversal 表、旋转因子。消除了每个元素重算
     cos/sin、以及每列重复 1000 次的二分查找。
  4) BMP 由"256 次 4 字节调色板 + 每行一次 fwrite"（每文件约 1081 次
     系统调用）改成内存里拼好后一次写出。这一项就占了原来 60 ms。
  5) 平均图的累加缓冲留在显存，只在最后回传一次；旧版每帧多回传 3.3 MB。
  6) 写 BMP 与下一帧的核函数重叠（软件流水）。

顺带修的：
  - compare_1000.py 里的目录名还是改名前的 1000_matlab_benchmark /
    1000_cuda，会直接报"标杆目录不存在"。已改为 matlab_benchmark / cuda，
    并补上 <=1 的 PASS/FAIL 判定与退出码。
  - build.bat 去掉 -lcufft，补上 cd /d "%~dp0"、错误码传递，
    并注明 -Xcompiler /utf-8 不可省（源码有中文注释）。

备份：优化前的 bscan_cuda1000.cu/.exe/build.bat、compare_1000.py 和
      12 张旧输出都保留在 dcs\_work\backup_1000\。
